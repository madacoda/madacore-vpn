# Step-by-Step Setup Guide: VPS & Windows Client
**Author:** Professional Network Engineer  
**Scope:** Initial installation, client integration, and validation for Dota 2, CS2, and Valorant.

---

## 1. Phase 1: What to do on your VPS (Server Side)

Depending on whether you want an automated CI/CD pipeline or a direct, manual deployment, choose **Option A** or **Option B**.

### Option A: CI/CD Deployment via GitHub (Recommended)
1. Create a repository on GitHub (private or public).
2. Push this project code from your local machine to your repository.
3. In GitHub, go to **Settings** $\rightarrow$ **Secrets and variables** $\rightarrow$ **Actions** $\rightarrow$ **New repository secret** and add:
   * `SERVER_HOST`: Your VPS Public IP.
   * `SERVER_USER`: Usually `root` or your sudo user.
   * `SSH_PRIVATE_KEY`: Your SSH Private Key.
   * `GHCR_PAT`: Your GitHub Personal Access Token (with `write:packages` and `read:packages` scopes).
4. The deployment will run automatically every time you push to the `main` branch.

### Option B: Manual Docker Deployment (Direct VPS setup)
If you don't want to use GitHub Actions, you can copy this project directly to the VPS and run it:
1. SSH into your VPS:
   ```cmd
   ssh root@<YOUR_VPS_IP>
   ```
2. Clone or upload this project directory to `/var/www/madacore-vpn`.
3. Set up the local environment variables:
   ```bash
   cd /var/www/madacore-vpn
   cp .env.example .env
   ```
4. Edit the `.env` file to replace `your-vps-ip-here` with your actual VPS IP:
   ```bash
   nano .env
   ```
5. Apply the server optimizations and launch the docker container:
   ```bash
   # Make the script executable
   chmod +x strategies/deploy.sh
   # Run the installer
   sudo ./strategies/deploy.sh
   ```

## 2. Phase 2: VPS Firewall Configuration

Regardless of how you deploy, your VPS hosting provider (e.g., DigitalOcean, Vultr, AWS, Linode, Hetzner) will block incoming traffic by default.

1. Log into your VPS provider's web console.
2. Go to the **Firewall / Security Groups** section associated with your VPS.
3. Add a new **Inbound Rule** with the following details:
   * **Protocol**: `UDP`
   * **Port**: `51820`
   * **Source**: `0.0.0.0/0` (Anywhere)
4. Save the rule.

## 3. Phase 3: What to do on your Windows Machine (Client Side)

Once the server is running, perform these steps to link your gaming PC to the VPS.

### Step 1: Install WireGuard
1. Go to the official WireGuard website: [https://www.wireguard.com/install/](https://www.wireguard.com/install/)
2. Download the **Windows Installer** (`.msi`).
3. Run the installer to complete the setup.

### Step 2: Retrieve your Client Config (`peer1.conf`) from the VPS
You need the client configuration profile generated by the VPS Docker container. Choose one of two methods:

* **Method 1: Copy via Command Line (Easiest)**
  Open **PowerShell** on your Windows PC and execute:
  ```powershell
  scp root@<YOUR_VPS_IP>:/var/www/madacore-vpn/config/peer1/peer1.conf C:\Users\Public\Downloads\peer1.conf
  ```
  *(Replace `<YOUR_VPS_IP>` with your actual VPS IP. The file will download to your public Downloads folder).*

* **Method 2: Visual QR Code Scan (For Mobile / Backup)**
  If you have SSH'd into your VPS, run:
  ```bash
  docker exec -it gaming-wireguard /app/show-peer 1
  ```
  A large QR code will render directly in your terminal. You can scan this using the WireGuard Mobile App.

### Step 3: Configure Split-Tunneling on Windows
By default, the client configuration will route **all** of your computer's internet traffic through the VPN. To optimize for gaming, we must modify it so **only** target games route through the VPS:

1. Open the **WireGuard** application on Windows.
2. Click **Import tunnel(s) from file** and select the downloaded `peer1.conf` file.
3. Select the imported tunnel and click the **Edit** button in the bottom right corner.
4. Locate the line under `[Peer]` starting with `AllowedIPs`.
5. Replace `AllowedIPs = 0.0.0.0/0` with the specific subnets of your game servers.

#### Recommended AllowedIPs configuration (Singapore / Southeast Asia Servers example):
```ini
# Add this under [Peer] in WireGuard Client editor
AllowedIPs = 10.0.0.0/24, 103.28.54.0/24, 103.10.124.0/23, 45.121.184.0/23, 16.228.0.0/15, 15.177.0.0/16
```
*(This routes the internal VPN subnet, Dota 2/CS2 Singapore, and Valorant Singapore subnets. For other regions, refer to the subnet tables in [gaming_vpn_strategy.md](file:///c:/laragon/www/madacore-vpn/strategies/gaming_vpn_strategy.md#L143-L177)).*

6. **Uncheck** "Block untunneled traffic (kill-switch)" if it is checked.
7. Click **Save**.

### Step 4: Activate the Tunnel
1. In the WireGuard app, click **Activate** next to your imported tunnel.
2. Once active, verify that your normal internet works (e.g. search something in your web browser).
3. If internet works, open a PowerShell terminal and ping the private VPN gateway to confirm connectivity:
   ```powershell
   ping 10.0.0.1
   ```
   *You should see replies with `< 1ms` or equal to your base ping to the VPS.*

## 4. Phase 4: In-Game Verification

To confirm that the games are successfully routing through your optimized VPS path:

### 1. Valorant
* Launch **Valorant**.
* Go to **Settings** $\rightarrow$ **Video** $\rightarrow$ **Stats**.
* Set **Network RTT** and **Network RTT Jitter** to **Text Only** or **Both**.
* Enter a match or Range, and observe the ping. It should be stable with minimal jitter.

### 2. Counter-Strike 2 (CS2)
* Launch **CS2**.
* Open the developer console (`~`) and type:
  ```text
  cl_hud_telemetry_serverping_show 2
  ```
* This displays a live ping overlay. Confirm the network routing.

### 3. Dota 2
* Launch **Dota 2**.
* Go to **Settings** $\rightarrow$ **Options** $\rightarrow$ **To Advanced Options** $\rightarrow$ **Miscellaneous**.
* Enable **Display Network Information**.
* In-game, your ping and packet loss percentages will display in the top-right corner.

## 5. Phase 5: Real-Time Traffic & Quality Monitoring

To monitor connection speed, latency, jitter, connected clients, and target server destinations in real-time, you can use either the terminal-based script or the containerized Web UI.

### Option A: Web UI Dashboard (Recommended - Accessed from Outside)
We have packaged the monitor as a sidecar container inside the [docker-compose.prod.yml](file:///c:/laragon/www/madacore-vpn/docker-compose.prod.yml). It connects to the Docker socket to inspect the VPN container, running a Flask server that binds locally on port `10000` (preventing direct, unencrypted public access).

1. **Deploy the Stack** (ensuring the `vpn-monitor` service is built):
   ```bash
   cd /var/www/madacore-vpn
   docker compose -f docker-compose.prod.yml up -d --build
   ```

2. **Configure Nginx Reverse Proxy on the Host VPS**:
   Because the Flask app displays live network connections and routing endpoints, you **MUST** secure the dashboard. We will set up Nginx as a reverse proxy with Basic Authentication and Let's Encrypt SSL.

   * **Step 2.1: Create Basic HTTP Authentication credentials**:
     Install Apache utilities (which include `htpasswd`) and generate a password file:
     ```bash
     sudo apt-get update && sudo apt-get install apache2-utils -y
     # Replace 'admin' with your preferred username. You will be prompted to type a password.
     sudo htpasswd -c /etc/nginx/.htpasswd_vpn_monitor admin
     ```

   * **Step 2.2: Add Nginx Server Block**:
     Create an Nginx configuration file at `/etc/nginx/sites-available/vpn-monitor`:
     ```nginx
     server {
         listen 80;
         server_name monitoring.madacoda.dev;

         # Secure with Basic Auth created in Step 2.1
         auth_basic "MadaCore VPN Monitor - Authorization Required";
         auth_basic_user_file /etc/nginx/.htpasswd_vpn_monitor;

         location / {
             proxy_pass http://127.0.0.1:10000;
             proxy_set_header Host $host;
             proxy_set_header X-Real-IP $remote_addr;
             proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
             proxy_set_header X-Forwarded-Proto $scheme;

             # Disable buffering to allow continuous telemetry streaming
             proxy_buffering off;
             proxy_read_timeout 3600s;
         }
     }
     ```
     Enable the site and reload Nginx:
     ```bash
     sudo ln -s /etc/nginx/sites-available/vpn-monitor /etc/nginx/sites-enabled/
     sudo nginx -t
     sudo systemctl reload nginx
     ```

   * **Step 2.3: Cloudflare Proxy & SSL Setup**:
     Since you are routing through Cloudflare, we don't need Certbot installed on the VPS host:
     - Point your `monitoring.madacoda.dev` DNS A-record to your VPS Public IP in your Cloudflare dashboard and ensure it is **Proxied (Orange Cloud)**.
     - In Cloudflare's **SSL/TLS** settings, set the mode to **Flexible** or **Full**.
     - Enable **Always Use HTTPS** under Cloudflare's Edge Certificates to enforce SSL redirection automatically.

3. **Access from Outside**:
   Open your browser and navigate to:
   ```text
   https://monitoring.madacoda.dev
   ```
   Log in with the credentials created in Step 2.1 to see the responsive, glassmorphic dark-mode web dashboard.

### What is Displayed:
- **🟢 Active Client IP**: Shows your VPN IP (e.g., `10.0.0.2`), public endpoint, and last handshake time.
- **⚡ Live Tunnel Latency**: Measures real-time ICMP ping RTT average and jitter directly to your client.
- **📊 Real-time Throughput (Speed)**: Shows download (Down) and upload (Up) speeds in Kbps.
- **🎯 Connected Host Targets**: Sniffs packets dynamically on the WireGuard interface, resolves the destination IPs via reverse DNS (e.g. `valve.net` or `riotgames.com`), and displays live speeds for each destination.
